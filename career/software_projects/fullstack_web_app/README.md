# Task Tracker — Full-Stack Web App

A small but complete full-stack application: a **Task Tracker** with a REST API and a
single-page React UI. Built to demonstrate the core skills of a full-stack developer —
designing a REST API, persisting data, wiring a frontend to a backend across CORS, and
packaging everything with Docker.

**Stack:** FastAPI · SQLAlchemy · SQLite · React · Vite · Docker

---

## Architecture

```
┌─────────────────────────┐         HTTP / JSON          ┌──────────────────────────┐
│      Frontend (SPA)      │  ───────────────────────▶    │        Backend API       │
│  React + Vite            │   GET/POST/PUT/DELETE         │  FastAPI (Uvicorn)       │
│  fetch() → api.js        │   /api/tasks                  │  Pydantic validation     │
│  Port 5173 (dev)         │  ◀───────────────────────    │  CORS middleware         │
│  Port 3000 (docker)      │         JSON responses        │  Port 8000               │
└─────────────────────────┘                               └───────────┬──────────────┘
                                                                       │ SQLAlchemy ORM
                                                                       ▼
                                                              ┌──────────────────┐
                                                              │   SQLite (file)  │
                                                              │   tasks.db       │
                                                              └──────────────────┘
```

- **Client–server split:** the React app is a pure static SPA. It holds no database
  logic — it only calls the JSON API. The FastAPI server owns all business logic and
  persistence. This separation lets each side be built, deployed, and scaled independently.
- **REST:** the `Task` resource is exposed at `/api/tasks` using standard HTTP verbs.
- **CORS:** the browser enforces the same-origin policy, so the API explicitly allows
  the frontend's origin via FastAPI's `CORSMiddleware`.

## API Endpoints

Base URL: `http://localhost:8000`

| Method | Path                | Description                    | Body                                  | Success |
|--------|---------------------|--------------------------------|---------------------------------------|---------|
| GET    | `/api/health`       | Health check                   | —                                     | 200     |
| GET    | `/api/tasks`        | List tasks (newest first)      | —                                     | 200     |
| POST   | `/api/tasks`        | Create a task                  | `{title, description?, priority?}`    | 201     |
| GET    | `/api/tasks/{id}`   | Get one task                   | —                                     | 200/404 |
| PUT    | `/api/tasks/{id}`   | Update a task (partial)        | `{title?, description?, priority?, completed?}` | 200/404 |
| DELETE | `/api/tasks/{id}`   | Delete a task                  | —                                     | 204/404 |

**Task fields:** `id`, `title` (1–200 chars, required), `description` (≤1000 chars),
`priority` (`low` \| `medium` \| `high`), `completed` (bool), `created_at`, `updated_at`.

Invalid payloads (e.g. empty title or bad priority) return **422** with a validation
error — automatically generated by Pydantic. Interactive docs are served at `/docs` (Swagger UI).

## Running locally

### Option A — Docker Compose (both services at once)

```bash
docker compose up --build
```

- Frontend: http://localhost:3000
- Backend API + Swagger docs: http://localhost:8000/docs

### Option B — run each service manually

**Backend**

```bash
cd backend
python -m venv venv
source venv/bin/activate       # Windows: venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload  # → http://localhost:8000
```

**Frontend** (in a second terminal)

```bash
cd frontend
npm install
npm run dev                    # → http://localhost:5173
```

The frontend reads the API base URL from `frontend/.env` (`VITE_API_URL`).

## Testing

```bash
cd backend
pip install -r requirements.txt
pytest -v
```

Tests use FastAPI's `TestClient` against an in-memory SQLite database (no file writes),
covering the full CRUD flow, validation errors (422), and not-found cases (404).

## UI description

A dark-themed single page:

- **Add form** at the top — title input, priority dropdown, optional description, "Add Task" button.
- **Toolbar** — a live "N tasks left" counter and `all / active / completed` filter buttons.
- **Task list** — each row has a completion checkbox, the title, a colored priority badge
  (green/amber/red), an optional description, and a delete (✕) button. Completed tasks are
  dimmed with strikethrough.

All actions (create, toggle complete, delete, filter) update React state immediately and
persist to the backend via the REST API.
